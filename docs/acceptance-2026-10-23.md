## 二、验收抓到的真 bug（已修）

**取消后谎报"还剩 0 项"**

```
修复前：moved=26  remaining=0   ← 但磁盘上还剩 274 个目录
修复后：moved=27  remaining=273 ← 与磁盘一致
```

原因：`deps.orphans_clean` 取消时只返回了 `moved/failed/bytes`，**漏了 `remaining`**；
`trash_paths` 一直有，独独这一处没有，所以界面上"已取消（部分完成）"后面的数字是错的。

已加回归测试 `tests/test_cancel_remaining.py`（两个函数各一条，且断言"账对得上 + 磁盘剩余一致"）。

## 三、性能实测（DoD 对照）

| 指标 | DoD | 实测 | 结论 |
|---|---|---|---|
| 内核冷启动 | — | **157 ms**（首次 352 ms） | 达标（历史上 105 ms） |
| `disk.summary` | — | **< 1 ms** | 达标 |
| `review.payload`（空缓存） | — | **744 ms** | 可接受（界面有进度层） |
| App 冷启动到出窗口 | **< 0.4 s** | **中位 975 ms**（5 次：763 / 917 / 975 / 977 / 987） | ❌ **未达标** |
| 交互（内核往返） | **< 50 ms** | ping 0.3 ms / summary < 1 ms | ✅（数据类命令另算，扫描类几百 ms） |

**为什么启动慢**：SwiftUI 窗口构建 + 首次请求时才 spawn 21 MB 的 PyInstaller 进程（150–350 ms），
两者串行叠加。

**试过并回退的方案**：启动时并行预热内核——实测**没有变快**（同一台机器 5 次采样仍在 0.7–1.6 s 波动，
机器忙时噪声比优化量还大）。已回退，理由写在 `App.swift` 注释里。

**要真达标只有两条路**：① 内核改成常驻 launchd agent（安装时注册）；② 内核用 Swift 重写。
两条都不在本次范围。
